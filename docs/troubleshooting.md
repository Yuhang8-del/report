# Troubleshooting

## No CUDA / `torch.cuda.is_available()=False`

Run the preflight through the intended Conda environment:

```powershell
.\scripts\start_gui.ps1 -PreflightOnly
conda run -n fruit-ssod python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
```

Install a CUDA-enabled PyTorch wheel compatible with the NVIDIA driver, then
restart the shell. Do not continue a GPU experiment on a CPU fallback: its
runtime evidence would not satisfy the RTX 3080 protocol.

## CUDA out of memory

Close other GPU programs, inspect `nvidia-smi`, release the GUI model, and retry
only with a controlled configuration adjustment approved by the experimental
protocol. A smaller batch/image size changes the experiment and must not be
silently substituted into the fixed matrix. Preserve failed run records.

## UNC data root cannot be reached

Confirm LAN/VPN connectivity and share credentials, then test the exact path:

```powershell
Test-Path '\\10.16.57.94\dataset2\lyg\detect_datasets'
```

Do not point `FRUIT_SSOD_DATA_ROOT` at an unrelated local directory just to
make a command pass. `-SkipDataRootReachability` is only for an intentional
offline diagnostic; it skips the UNC share reachability and capacity checks but
does not waive the data requirement for a real run. Local artifact checks and
the artifact write/delete probe still run.

## Missing or rejected weights

`FRUIT_SSOD_PRETRAINED_WEIGHTS` is required before matrix validation/training.
It must point to the approved readable `.pt` initialization checkpoint. GUI
model selection likewise requires an existing five-class compatible `.pt`
checkpoint. Verify path quoting and use a model generated by this project; do
not rename an arbitrary file to `.pt`.

## Unsupported or unreadable video

The demo supports file-based video only. Re-encode the input to a standard local
MP4/AVI/MOV format that the installed OpenCV backend can read, verify the file
opens in a player, and retry. There is intentionally no camera fallback. Keep
the error message and source file when diagnosing a codec issue.

## Invalid YAML or unset environment variable

The project expands `${FRUIT_SSOD_DATA_ROOT}`, `${FRUIT_SSOD_ARTIFACT_ROOT}`, and
`${FRUIT_SSOD_PRETRAINED_WEIGHTS}` in controlled configs. Set the variables in
the same PowerShell process before invoking a launcher, or pass the documented
launcher parameters. Do not hand-edit generated experiment YAML files; rerun
the relevant configuration validation and restore a checked-in YAML if it was
changed.

## Conda environment is not found or imports global packages

Pass the existing environment explicitly:

```powershell
.\scripts\start_gui.ps1 -CondaEnvironment my-existing-env -PreflightOnly
```

Install the project requirements in that environment and set
`PYTHONNOUSERSITE=1` using `conda env config vars set -n my-existing-env
PYTHONNOUSERSITE=1`. Confirm with `conda run -n my-existing-env python -m pip
check`. Avoid relying on packages installed in a different base/user Python.

## Results are missing or a metric is lower than expected

Do not infer success from a training console line. Inspect the run record,
evaluation evidence, benchmark JSON, and immutable aggregate package under the
artifact root. The real-data experiment queue has not yet been executed merely
because the repository code is present; report pass/fail truthfully from the
acceptance JSON.
